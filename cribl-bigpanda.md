# Cribl Stream → BigPanda Webhook Integration Lab

## 1. Lab Overview

This hands-on lab walks through the complete workflow for integrating **Cribl Stream with BigPanda**:

```text
Cribl Stream
    |
    | Webhook / HTTP POST
    v
BigPanda Integration
    |
    v
BigPanda Alert
    |
    | Correlation / Deduplication
    v
BigPanda Incident
    |
    v
Validation
```

The lab follows the Cribl Stream **BigPanda/Webhook Integration** procedure and uses the BigPanda Alerts API.

## 2. Objectives

By completing this lab, you will be able to:

* Create a BigPanda Cribl integration.
* Generate a BigPanda App Key.
* Obtain the BigPanda authentication/access token.
* Configure a Cribl Stream Webhook Destination.
* Configure authentication securely.
* Send a test alert from Cribl to BigPanda.
* Verify the alert in BigPanda.
* Understand BigPanda Primary and Secondary properties.
* Demonstrate alert deduplication.
* Explore alert correlation into an Incident.
* Perform end-to-end troubleshooting and validation.

# 3. Prerequisites

You need:

### BigPanda

* BigPanda Cloud instance

### Cribl

* Cribl Cloud or Cribl Stream environment
* Permission to configure a Worker Group
* Permission to create a Webhook Destination
* Permission to Commit & Deploy

### Important

The BigPanda **App Key** and **Access Token** are different values.

The App Key identifies the integration/application.

The Access Token is used for HTTP authentication.

Do not confuse the two.

# 15. Exercise 11 — Understand Primary and Secondary Properties

BigPanda processes Primary and Secondary properties when an alert is received.

The default properties described in the Cribl documentation are:

```text
Primary Property   = host
Secondary Property = check
```

For our test:

```text
host  = production-database-1
check = CPU overloaded
```

Therefore the alert identity can be thought of as:

```text
production-database-1
        +
CPU overloaded
```

This becomes important when multiple alerts arrive.

## Observe BigPanda

Return to the Incident.

Compare the original alert and the second event.

### Question

Does BigPanda create a completely independent Incident for the duplicate?

### Expected concept

BigPanda performs alert deduplication based on the Primary and Secondary properties.

When the same Primary and Secondary properties are received again, BigPanda treats the events as duplicates rather than displaying each one as a separate occurrence in the Incident Console.

# 19. Exercise 15 — Explore Correlation

Now move from **deduplication** to **correlation**.

The conceptual flow is:

```text
Alert 1 ─┐
         |
Alert 2 ─┼──> Correlation ──> Incident
         |
Alert 3 ─┘
```

The objective is to determine whether multiple related alerts should be represented together as an Incident.

In BigPanda, examine the Incident and its Alerts.

Look for common properties such as:

* Host
* Application
* Service
* Cluster
* Check
* Source
* Other normalized properties

### Investigation question

Suppose these alerts arrive:

```text
web-server-01 → CPU high
web-server-01 → Memory high
web-server-01 → Disk high
```

Would these potentially represent one underlying problem or three unrelated problems?

Discuss how correlation could help an operations team reduce alert noise.

# 29. Architecture Takeaway

The most important concept from this lab is that the integration has several distinct stages:

```text
                    CRIBL
                      |
                      | Webhook
                      v
              +---------------+
              |   BigPanda    |
              |     Alert     |
              +-------+-------+
                      |
             Primary/Secondary
                 Properties
                      |
             +--------+--------+
             |                 |
        Deduplication      Correlation
             |                 |
             +--------+--------+
                      |
                      v
                INCIDENT
```

**Cribl's responsibility:** generate and deliver the event/alert payload.

**BigPanda's responsibility:** ingest, normalize/process, deduplicate, correlate, and present the resulting operational incident.

The success criterion for the complete lab is therefore not merely **"Cribl says the webhook test succeeded."**

The true end-to-end validation is:

> **Cribl Webhook → BigPanda Alert → BigPanda processing → Incident visible in the BigPanda Incident Console.**
